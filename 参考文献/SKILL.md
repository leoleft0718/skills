# 参考文献スライド作成スキル

学術論文の内容を **Marp Markdown** (`theme: custom`) でゼミ紹介スライドにまとめる。
Marp スキル（`~/.claude/skills/marp/`）のテーマ・書式ルールを継承し、
**初見の聴衆が「この論文は何を言いたいのか」を1回で理解できる** ことを最優先とする。

## いつ使うか

- ユーザーが「参考文献」「論文紹介」「論文スライド」「paper review」「文献スライド」と言ったとき
- 論文の要約スライドを作成・修正したいとき

## 初見向けの5原則

これらは **厳守ルール** であり、すべてのスライドで一貫して適用する。

### 原則1: 身近な例えから入る

2枚目のスライド（表紙の直後）は、論文の問いを **日常的な例え** で説明する。

- 専門用語を使わず、誰でも想像できるシチュエーションで論文の問いを言い換える
- 例: 東大医学部の教授に「この問題、中学生にとって難しい？」と聞いても、自分が簡単に解けすぎて学生のつまずきがわからない
- このスライドを見るだけで、**残りのスライドを理解するための土台** ができるように書く

**書き方**:
```markdown
<!-- _header: この論文は何を問うているか -->

# 見出し（論文の問いを平易に）

> 身近な例え

- 論文の問いを箇条書きで
- なぜそれが難しいかを箇条書きで
```

### 原則2: 専門用語は必ず平易に言い換える

Spearman ρ, AUROC, IRT などの **指標・手法名** を使う場合は、必ず直後に **「どういうこと」の説明** を添える。

| 専門用語 | 言い換え例 |
|---|---|
| Spearman ρ = 1.0 | 「順位が完璧に一致」 |
| Spearman ρ = 0 | 「当てずっぽうと同じ」 |
| AUROC = 0.5 | 「コイン投げと同じ」 |
| AUROC = 1.0 | 「完璧に当てられる」 |
| IRT | 「正答率から難易度を逆算する統計手法」 |
| コールドスタート | 「データが何もない状態から始める問題」 |
| ゼロショット | 「事前のデータや例を一切与えずに推論させること」 |

表や数値の直後に引用ブロックで **一言で意味を言い切る**:
```markdown
> **0.28 は「ほぼ当たっていない」**
```

### 原則3: 1スライド1メッセージ

各スライドは **1つの主張** だけを伝える。

- スライドの H1 見出し自体が主張になるように書く
- 「Finding 1: 系統的ミスアラインメント」のようなラベルだけの見出しは避ける
- 見出しを読むだけで **「このスライドは何を言いたいか」** がわかるようにする

**良い例**:
```
# AI の予測は、人間の感覚とずれている
```

**悪い例**:
```
# Finding 1: 系統的ミスアラインメント
```

### 原則4: 数値は意味とセットで

表や数値を提示するスライドでは、**数値の羅列だけで終わらせない**。

- 表の直後に **2〜3行の箇条書き** で「この数値は何を意味するか」を説明
- 最も重要な数値には `<span class="c-ng">` や `<span class="c-accent">` で色を付けて視線を誘導
- 数値の「閾値」を明示（例: 0.28 は弱い、0.70 以上なら強い、等）

### 原則5: 結論は対比で見せる

結論スライドでは、**発見の羅列** だけでなく **「で、どういうことか」** を同じスライド内に対比する。

```markdown
<div class="flex sb">
<div>

### 発見
1. ...
2. ...

</div>
<div>

### どういうこと？
一言で言うと...

</div>
</div>
```

## スライド構成（推奨テンプレート）

論文紹介スライドは以下の構成を基本とする。論文の内容に合わせて枚数は調整してよい。

| 順序 | スライド | 内容 | 原則 |
|---|---|---|---|
| 1 | 表紙 | タイトル・著者・発表者情報 | — |
| 2 | 問いの直感 | 身近な例えで論文の問いを説明 | 原則1 |
| 3 | 背景・動機 | なぜこの問題が重要か | 原則2 |
| 4 | 実験の全体像 | 何をどう調べたか（簡潔に） | 原則2 |
| 5..N | 結果（Finding毎） | 1 Finding = 1スライド原則 | 原則3,4 |
| N+1 | 結論 | 発見と「どういうことか」の対比 | 原則5 |
| N+2 | 自研究との関連 | 発表者の研究との接続・示唆 | — |
| N+3 | 参考文献 | 引用・リンク | — |

## 厳守ルール

Marp スキルの厳守ルールを **すべて継承** する。追加で以下を守ること。

1. **フロントマターは Marp スキルに準拠**

```yaml
---
marp: true
theme: custom
paginate: true
---
```

2. **表紙の `_class: title`・`_paginate: false` は Marp スキルに準拠**

3. **5原則を満たすまでスライドを「完成」としない**
   - 身近な例えがない → 原則1違反
   - 専門用語に説明がない → 原則2違反
   - 見出しがラベルだけ → 原則3違反
   - 数値の意味がない → 原則4違反
   - 結論に対比がない → 原則5違反

4. **自研究との関連スライドを必ず含める**
   - 発表者の研究（卒論・M1等）との接続点を明示
   - 論文の知見が自分の研究にどう影響するかを一言で

5. **参考文献は IEEE 形式で末尾に配置**
   - プロジェクトページや GitHub リンクがあれば併記

6. **README.md を同梱する**
   - `~/.claude/skills/marp/templates/README.md.tpl` をベースに生成
   - 既存の場合は上書きしない

7. **変更後は必ず PDF エクスポートを実行する**

## 生成手順（モデル向け）

1. 論文の全文（または要約メモ）を読み、**論文の問い・手法・結果・結論** を把握する。
2. 論文の問いを **身近な例え** に言い換える（原則1）。
3. 上記の推奨構成に沿ってスライド構成を決める。
4. `~/.claude/skills/marp/templates/title.md` を表紙として配置。
5. 2枚目に「問いの直感」スライドを書く。
6. 背景・実験設計のスライドを書く（専門用語は平易に言い換え）。
7. Finding ごとにスライドを書く。1 Finding = 1スライドを基本とし、内容が多い場合は2枚に分割してよい。
8. 結論スライドを2段組みで書く（発見 vs どういうことか）。
9. 自研究との関連スライドを書く。
10. 参考文献スライドを書く。
11. 全スライドの H1 見出しを確認し、ラベルだけの見出しがないか検査する（原則3）。
12. `paginate` / `_paginate: false` の整合をチェックする。
13. README.md を同階層に生成する。
14. **PDF エクスポートを実行** し、結果をユーザーに提示する。
15. ビルドコマンドを提示する。

## ビルドコマンド

Marp スキルのテーマを `--theme-set` で渡す。

```bash
# プレビュー（監視モード）
marp --theme-set ~/.claude/skills/marp/themes/custom.css -w slides.md

# PDF
marp --theme-set ~/.claude/skills/marp/themes/custom.css --pdf slides.md

# PPTX
marp --theme-set ~/.claude/skills/marp/themes/custom.css --pptx slides.md

# HTML（単体配布）
marp --theme-set ~/.claude/skills/marp/themes/custom.css --html slides.md
```

ローカル画像を埋め込む PDF/PPTX の場合は `--allow-local-files` を追加する。
